# R-15　共通データモデルと品質管理ルールのたたき台

- 対象は [Issue #15](https://github.com/Olein-jp/japan-infection-watch/issues/15)。確認日 2026-11-24（JST）。JIHS の週次定点と厚労省の学校欠席者数の資料に基づく設計案・架空データ検証まで完了。学校関連データの実測と公開条件の確定は継続中。
- [データモデル案](../schemas/observations.md)に、観測キー、分母、対象範囲、版、欠損状態、公開可否、GitHub Pages 向けのファイル分割・manifest を記録した。[地域マスターの照合結果](R-14-master-joins.md)のうち、検証済みの行政区域と報告区分の区別を使用した。

資料はいずれも 2026-11-24（JST）に確認した既存の一次情報・検証結果を使った。統合モデルの試験に用いた観測値、版 ID、ハッシュ、添付 JSON の例は架空。実データを公開用スキーマに変換してはいない。

## 品質管理の検証

| ルール | 架空データの結果 | 運用案 |
|---|---|---|
| 同一版の観測キーは一意 | 同一版の重複はエラー。別版の同じ観測は保存できる | 同一原本の再取得は版を増やさず、試行履歴を記録 |
| 訂正は比較対象と訂正根拠を照合 | 同じ観測の旧版0・新版2を保持し、差分2を確認。別資料への訂正リンクと循環はエラー | 訂正通知と版の関係を確認し、採用候補を更新。累計の前週との差を、そのまま週次値とみなす計算は避ける |
| 数値と欠損の整合 | 明示ゼロと小数の表示上のゼロを保持。空欄・ハイフン・計数不明・未報告・秘匿・対象外は null。必須セルの欠落をエラーにした | 出典の根拠で状態を付ける。必須の範囲は資料ごとに定め、仕様上の欠損を許容する |
| 原表照合、列変更、日付逆転 | 原表トークンと正規化結果の違い、観測の列名変更、対象日の逆転を検出 | 取得元の生の列・見出し・期間は #9・#10 のように正規化前にも検証し、変更時は候補版を保留 |
| 集計・地域の照合 | 架空の県報告区分4＋別掲市2＝全国6と確認。集計差・版混在はエラー、計数不明があれば検算不能 | 同じ資料・版・指標・期間・施設区分で、排他的な内訳を確認できた場合だけ加算。検算不能なら掲載計を保持して検算状態と根拠を付ける |
| 急変検知 | 同一系列の連続週で例示閾値（差10以上かつ3倍以上）に達したとき要確認。欠損は比較不能 | 急変単独で自動修正・削除をしない。対象の変更や報告遅れを照合する。実運用の閾値と処理は系列ごとに検証 |

リポジトリルートから Python 3.13.5 の標準ライブラリのみで実行した。

```sh
python3 -m unittest discover -s poc/data-model -v
```

15件のテストが通過した。入力は [架空観測の JSON](../../tests/fixtures/r15-observations.json)、検証コードは [PoC](../../poc/data-model/verify_rules.py)。公開ファイルの生成・配信、manifest のビルド時検査、期限・性能の測定は設計案の段階。

## 残っている判断

- #5〜#7 と #14 の学校側の照合後に、学校保健会から得られる地域・学校種別・期間・閉鎖種別、分母、同じ学校が複数の区分に入る場合の集計を確定する。学校側の未確認の項目は案として保持する。
- #16 では資料別の公開可否・訂正発見・許容される保存先と保存期間・失敗時の復旧を検証する。#17 では架空データで分割、base path、manifest の読込、転送量・ビルド時間を検証する。
- #15 の受入基準のうち、検証済み資料のモデル案、架空データの品質検証、公開 JSON の分割案と鮮度の項目を記録した。学校関連の定義・実データ照合を残しているため Issue は継続中。
