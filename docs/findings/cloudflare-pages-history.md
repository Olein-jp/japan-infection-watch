# 静的ホスティングの無料枠と週次履歴の設計比較

確認日 2026-11-25（JST）。[F-002 の静的生成](F-002-static-preview.md)と[初回公開の判定](O-001-release-readiness.md)を前提に、履歴期間と JSON の分割方式を比較した。公開先と本番の分割方式を決めるための資料。

## 結論

- 初期版では、全国・47都道府県の週次推移を直近6か月まで掲載し、それ以前は JIHS の速報一覧へ案内する。既存の地域・月・疾患別で生成した架空データ一式は7,417ファイル、約22.4 MB。採用する GitHub Pages の公開サイト上限1 GBを下回り、比較対象の Cloudflare Pages の無料枠2万ファイルにも収まる。[週次履歴の仕様](../specifications/mvp.md#週次履歴の表示範囲)・[GitHub Pages の上限](https://docs.github.com/ja/pages/getting-started-with-github-pages/github-pages-limits)・[Cloudflare Pages の上限](https://developers.cloudflare.com/pages/platform/limits/#files)
- Cloudflare Pages を採用する場合、公開一式が**16,000ファイル**または最大1ファイルが**20 MiB**に近づく段階で見直し、上限を超えた候補のアップロードは保留する。この値は公式上限の約8割に取った運用案。Cloudflare の公式上限は2万ファイル、1ファイル25 MiB。管理画面からのアップロードは1,000件までなので、計測した各構成の一式は Wrangler の Direct Upload を前提とする。[アップロード方法別の制限](https://developers.cloudflare.com/pages/get-started/direct-upload/#limits)
- 疾患・地域・系列の追加で配布規模が見直しの目安に近づいた場合は、6か月の表示範囲を維持したまま履歴の JSON を地域・月でまとめる案を比較する。最新値は配信対象の HTML に残す。都道府県ページの初期表示で取得する履歴は、その地域のインフルエンザだけに絞る。

## 計測結果

全国と47都道府県、19疾患、各2指標。2030年2月3日までの6か月間は2029年8月3日以降に終了する27報告週で、月別の配信ファイルは8月から2月までの7か月にまたがる。同じ終了日の4か月間は18報告週。比較用の26週と52週も含め、架空 CSV から正規化した。現在のファイルは HTML、CSS、JS、manifest、地域索引、最新 JSON と履歴を含む。地域・月まとめ案では、履歴にその地域・月の全疾患の行と週の来歴を持たせ、来歴を月内で共有する。最新 JSON と HTML、CSS、JS はそのまま比較に含めた。

| 履歴期間・方式 | 一式のファイル数 | 一式の未圧縮サイズ | 最初の履歴操作・gzip 中央値 | 索引取得後の履歴1件・gzip 中央値 |
|---|---:|---:|---:|---:|
| 6か月・地域／月／疾患別（現行） | 7,417 | 22.37 MB | 8.25 KB | 0.60 KB |
| 6か月・地域／月別にまとめる | 1,369 | 15.42 MB | 3.36 KB | 1.71 KB |
| 4か月・地域／月／疾患別（現行） | 5,593 | 15.46 MB | 6.43 KB | 0.60 KB |
| 4か月・地域／月別にまとめる | 1,273 | 10.74 MB | 3.25 KB | 1.71 KB |
| 52週・地域／月／疾患別（現行） | 12,889 | 41.70 MB | 13.67 KB | 0.61 KB |
| 52週・地域／月別にまとめる | 1,657 | 28.43 MB | 3.67 KB | 1.71 KB |
| 26週・地域／月／疾患別（現行） | 7,417 | 21.67 MB | 8.26 KB | 0.60 KB |
| 26週・地域／月別にまとめる | 1,369 | 14.91 MB | 3.36 KB | 1.71 KB |

52週では期間終了日が最大13か月、26週では今回は7か月にまたがった。現行52週の最大ファイルは地域索引の59,581バイト。まとめ案は最大の月別履歴53,927バイト、最大の地域索引6,965バイトだった。最初の履歴操作は地域索引と選択月の履歴 JSON の合計。索引取得後の値は、まだ取得していない履歴 JSON だけの大きさ。まとめ案の現行データ構成では、同じ地域・同じ月の別疾患の表示に取得した JSON を再利用できる設計が可能。

現行方式はローカル生成した一式を SHA-256 と参照整合性まで検証した。まとめ案は同じ行を JSON に再パックし、索引と manifest を含めて計測した。ブラウザへの実装や Cloudflare へのアップロードは未実施。KB・MB は十進単位、gzip は各ファイルを個別に圧縮したサイズで、実配信の圧縮・キャッシュ・通信時間を示す値ではない。

## 市区町村を拡張する場合

[R-17 の市区町村日次の試算](R-17-pages-architecture.md#容量時間費用の試算)では、1,741地域の日次1年分は約13.6万ファイル。全疾患を地域・月単位にまとめても、13か月にまたがる構成では履歴だけで22,633ファイルとなる。日次を全国規模に広げるときは、地域・四半期単位にまとめるか、地域や公開期間を絞ることを別途比較する。四半期分をまとめる方式はファイル数を減らせる一方、一度の履歴取得量が増えるため、日次の実データの権利・粒度と読み込み量が確認できてから採否を決める。

## 再現手順

リポジトリのルートから実行。Python 3.13.5 の標準ライブラリを使い、架空のサイトは一時領域に生成する。26週・52週の値は6か月制限を導入する前の比較記録。現行コードでは画面に案内が加わったため、HTML のサイズは表の計測時点と異なる。

```sh
PYTHONPATH=tests:. python3 -B poc/pages/measure_history.py --months 4
PYTHONPATH=tests:. python3 -B poc/pages/measure_history.py --months 6
```
