# D-001　初期版の開発範囲と入力の利用条件

2026-11-24（JST）に依頼者が [R-19 の仕様案](../findings/R-19-mvp-specification.md)での開発を承認した。現在は設計・開発段階。[D-001（#20）](https://github.com/Olein-jp/japan-infection-watch/issues/20) は2026-11-25（JST）に完了した。実データの公開と定期取得は、資料ごとの利用条件を確定したうえで別途承認を得る。

## 採用技術と着手範囲

- Python で入力の正規化、品質検査、静的生成を行う。画面は静的 HTML・CSS・JavaScript。GitHub Actions の標準 Linux runner と GitHub Pages の標準アドレスを運用の基本とし、追加費用は月0円を前提とする。
- 最初に実装するのは、架空の JIHS 週次定点 CSV 形式から共通モデルへの変換と検査。全国・都道府県、報告件数・定点当たり報告数、出典・版・報告週・単位・粒度・欠損状態を扱う。値、版、出典は架空であることを明示し、実データには公開可否の判定を適用する。網羅的な疾患・履歴の取り込みは条件を満たした後に拡張する。
- 架空入力だけで、最新・履歴 JSON と静的ページのローカル生成、地域や疾患ページの直リンク・404、遅延読み込み、公開不可の入力の除外、既存配布版の維持を実装・検証できる。架空の入力・成果物も本番公開対象から除く。本番入力の自動取得や公開はここでは始めない。[公開アーキテクチャ案](../architecture/mvp-publication.md)
