# プロジェクト範囲

47都道府県と市区町村を対象に、政令指定都市の行政区・特別区も考慮する。小中高の学級閉鎖・学年閉鎖・学校閉鎖、感染症発生動向、学校の出席停止人数・閉鎖クラス数・利用可能な割合指標を候補とする。日次・週次の推移、地図、地域比較、疾患別・地域別ページを想定する。学校別表示は将来の選択肢とし、児童生徒を識別できる情報は扱わない。無料閲覧を想定し、利用者登録、位置情報収集、追跡は MVP の対象外。収益化は保留する。

初期構築 → R-01〜R-17 の調査と技術検証 → R-18 の実現可能性評価 → R-19 の開発仕様案 → 依頼者の Go/No-Go → 設計・開発 Issue → MVP 開発 → 公開承認 → 運用と追加調査。同一リポジトリで成果物、Issue、Git 履歴を維持し、開発 Issue から根拠の調査 ID と成果物へリンクする。

MVP の公開・更新・保管は、追加の運営費が月0円に収まる範囲を前提とする。公開リポジトリと GitHub Free、Pages の標準ドメイン、標準 GitHub-hosted runner を基本構成とする。無料枠で継続できる地域、履歴期間、更新頻度を R-18 で評価し、R-19 で容量・課金の判定と超過時の対応を仕様化する。[無料枠での運用設計](architecture/pages-layout.md#無料枠での運用設計)

## GitHub Pages の構成

公式 API・CSV・PDF・公開集計ビュー → Actions での取得・正規化・品質検証・公開可否判定 → 検証済みデータ → 静的生成 → 専用成果物 → GitHub Pages。利用者には HTML、CSS、JS、読み取り専用 JSON、地図データを配信する。Node.js や Python は取得・ビルド時の候補とし、公開環境は静的ファイルで構成する。提供元への直接アクセスと認証情報の配信を避ける。

Astro、Vite、静的 HTML + JS などを R-17/R-19 で比較する。地域ページの直リンクと再読み込み、リポジトリ名を含む base path、末尾スラッシュ、404、アセット参照、将来の独自ドメインを検証する。`docs/` は調査・設計用とし、`upload-pages-artifact` と `deploy-pages` には公開専用成果物（例 `dist/`）を渡す。将来の配置候補は `apps/web/`、`apps/collector/`、`packages/data-model/`、`packages/data-normalizer/`、`data/public/`、`.github/workflows/`。PoC は分離し、転用時はテスト・例外処理・利用条件を確認する。

## 更新と復旧

提供元別の日次・週次の公表頻度と許容アクセス頻度に合わせ、JST/UTC の変換、毎時00分付近の回避、遅延・未実行、`workflow_dispatch`、活動停止による無効化の検知と復旧を設計する。60日無活動など schedule の現行条件は R-17 で確認する。不要なコミットによる回避は行わない。

収集・検証・公開の段階ごとに同時実行を制御し、タイムアウト、再試行上限、バックオフ、拒否時の停止、冪等性、訂正版の反映を設計する。異常な欠損、列変更、日付逆転、急変、集計不一致を検知し、失敗時は前回の検証済みデータと公開成功版を保持する。部分更新の扱いと提供元別の鮮度を示し、最終取得成功日時、データ対象日、提供元更新日、サイト生成日時を分ける。閲覧時の古さ判定、失敗通知、手動復旧、ロールバックを設計する。`GITHUB_TOKEN` 経由の push による別ワークフロー起動を前提とせず、同一ワークフローでの接続も比較する。最小権限、ブランチ保護、依存 Action の固定、公開前検証を設計に含める。

## データ配布と容量

日付、地域、疾患、提供元、指標、単位、版、対象範囲を使って正規化する。公開用 JSON は地域・年月・疾患などで分割し、必要な範囲を読み込む。最新スナップショット、期間別履歴、出典・鮮度・対応地域の manifest を分離する。地図データも簡略化や分割を検討し、スマートフォンで負荷を計測する。

保存・再配布可能なデータだけを履歴化する。小容量スナップショットなどの永続化先を比較し、Actions cache や期限付き artifact のみに依存しない。保存期限、訂正、削除、Git 履歴残存、リポジトリ肥大化を評価する。R-17 で公式制限（公開サイト最大 1 GB、月間帯域 100 GB のソフト上限、デプロイ時間など、数値は確認対象）、Actions 実行時間・ストレージ・公開範囲別費用を確認し、全国・複数疾患・日次履歴の容量を試算する。広告や有料機能は GitHub の利用条件との適合確認と承認を要する。Pages で成立しない場合は根拠と代替案を報告する。

## 公開範囲と表示品質

初期は Private 推奨だが、現状の公開範囲を維持する。リポジトリとサイトの公開範囲、GitHub Free を含むプラン条件、Private リポジトリからのサイト公開条件は R-17 で確認する。公開範囲変更と Pages 有効化には依頼者の承認が必要。公開前に Git 全履歴、Issue・コメント、Actions ログ、公開成果物を監査し、再配布不可データ、秘密情報、未公開資料の混入を防ぐ。

データなしとゼロを区別する。学校の集計と住民全体の感染症動向、保健所と市町村、閉鎖中クラス数と閉鎖実施学校数・新規閉鎖件数を分ける。学年閉鎖を分離できない値は合算と表示する。地図は欠損地域を識別できる凡例・表・テキストを備え、色への依存を避ける。公式の警報・注意報と独自指標を区別し、出典、対象集計期間、施設・地域、更新時刻、公開範囲を明示する。
